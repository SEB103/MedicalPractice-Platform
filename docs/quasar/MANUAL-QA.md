# Ручная приёмка

Браузерная проверка и скриншоты не выполнялись в среде реализации: отсутствует
поддерживаемая browser-control capability. Следующие пункты пока НЕ подтверждены визуально.

Проверить ширины 390, 768, 1440 и 1920 px, все три темы в light/dark и System.

1. Главная → услуги → детали → врач → практика → контакты → FAQ → юридические страницы.
2. Вход виден в Header на узком экране; мобильное меню открывается и закрывается.
3. Anmelden → Als Demopatient anmelden → Dashboard → детали ближайшего приёма.
4. Календарь: вид услуги, дата, слот, подтверждение → новая запись в деталях и списке.
5. Перенос: выбрать новый слот → исходный отменён, новая запись pending.
6. Отмена: сначала отклонить диалог (ничего не меняется), затем подтвердить.
7. Переключить фильтры списка; проверить пустое состояние после отмены всех будущих.
8. Demo steuern → Nächste Anfrage: Fehler → перейти в список. Проверить retry.
9. При имитации сбоя бронирования/переноса запись не меняется; повторить запрос.
10. Профиль: выбрать другой синтетический адрес, сохранить, перезагрузить.
11. Настройки: уведомления, тема, режим; переходы и reload сохраняют состояние.
12. Logout → публичная главная; Back на кабинет снова ведёт на вход.
13. Регистрация → pending → попытка открыть кабинет → pending → Freigabe simulieren.
14. Прямые URL и Back/Forward; неизвестный URL → 404.
15. Tab/Shift+Tab, видимый focus, Escape и возврат focus после диалога,
    screen-reader объявления статуса/ошибок, 200% zoom, prefers-reduced-motion.
16. System: изменить режим ОС при открытой странице; проверить цвета контролов/фона.
17. Проверить contrast всех шести палитр. WCAG 2.2 AA — цель, не подтверждённая сертификация.

## Дополнительно для обновления

18. На Dashboard выбрать день с отметкой и открыть детали соответствующего приёма.
19. Для 20-, 45-, 50- и 60-минутных услуг проверить конец слота, перерыв и соседние записи.
20. Отпуск, сокращённый день и полностью занятый день недоступны для записи.
21. После смены услуги прежний слот очищается; перенос не теряет исходную запись при ошибке.
22. Мобильные нижние вкладки, меню и Logout остаются доступны при открытом кабинете.
23. Проверить новые страницы Datenschutz пациентов и доступности, ссылки и оглавление.
24. Проверить фото с разными srcset/focal point и недоступным URL после подключения CMS.
