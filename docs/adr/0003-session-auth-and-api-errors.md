# ADR-0003: Session authentication, error envelope and OpenAPI

Date: 2026-10-23
Status: Accepted

## Context
The Quasar SPA and Django run on one domain behind a reverse proxy (development: Quasar dev-server proxy
for `/api`). A mobile app is not planned yet.

## Options considered
- Token/JWT auth: needed for mobile apps, but tokens in browser storage are a risk.
- Django session cookie + CSRF: built in, HttpOnly cookie, no CORS on one domain.

## Decision
- Session authentication with CSRF. Login, registration and password reset enforce CSRF although the user
  is anonymous; the frontend first calls `GET /api/v1/auth/csrf/`.
- Anonymous requests to protected endpoints return **401** (custom `SessionAuthentication401`).
- All errors use `{"code": str, "message": str, "fields": dict}`.
- Registration and password reset answer identically for known and unknown e-mail addresses; login uses
  one generic error for wrong password, unknown e-mail and blocked accounts. Rate limit: `auth` scope.
- OpenAPI is generated by drf-spectacular and committed as `docs/api/openapi.yaml`; CI fails if it is
  outdated. Frontend types are derived from it.

## Consequences
The rate limiter uses the default cache (per process); production needs a shared cache. Token auth for a
future mobile app requires a new ADR.
